博客工程化实践

从定位、信息架构、主题体验到发布门禁，记录这个 Hexo 博客如何被当作长期工程持续维护。

这个专题记录 Ryuho 博客自身的工程化过程。

它不是一套“最佳 Hexo 配置”，而是一条真实演进路径：先让站点定位清楚，再整理阅读体验，随后补搜索、专题、部署和质量检查，最后主动停止没有需求支撑的功能扩张。

阅读路径

1. 先明确为什么要维护

个人博客值得长期维护的前提，不是页面足够漂亮，而是它能持续沉淀技术判断、项目经验和写作成果。

关联阅读：小站开张：把个人博客当作长期工程

2. 整理信息架构

首页、分类、标签和关于页承担不同责任。先让读者知道站点关注什么，再考虑更多视觉细节。

关联阅读：站点整理日志：先把信息架构理顺

3. 让主题服务阅读

卡片、时间线、深色模式和阅读状态都只是工具。它们的共同目标，是降低浏览和连续阅读成本。

关联阅读：站点整理日志：让主题服务阅读体验

4. 把博客当作工程项目

当内容和页面增多后，构建、部署、SEO、搜索和内容质量需要进入同一条维护流程。

关联阅读：把个人博客当作工程项目维护

5. 建立发布门禁

最终的质量基线不是“Hexo 没报错”，而是关键页面、链接、资源、元数据、内容和两套部署配置都经过自动验证。

关联阅读：从能构建到敢发布：为 Hexo 博客建立质量门禁

6. 用最小依赖解决内容搜索

站内搜索不一定需要大型前端库。构建期索引、简单权重、输出转义和双路径验证，足以覆盖当前内容规模。

关联阅读：静态博客搜索为什么选择零 CDN 依赖

7. 为静态站增加有限的离线韧性

service worker 采用核心资源预缓存和 network-first 策略，优先保持内容新鲜，在网络失败时回退到已缓存页面。

关联阅读：个人静态站的离线策略：为什么选择网络优先

8. 把图片压缩变成可回退的构建步骤

保留高质量源码，只优化 public 产物；先写临时文件，只在体积确实下降时替换，并用审计检查尺寸和真实格式。

关联阅读：图片优化应该发生在源码还是构建产物

9. 用内容元数据生成相关推荐

共享标签每个加 2 分，共享分类加 1 分，同分时优先较新文章；没有主题交集时，诚实退化为最近更新。

关联阅读：零后端的相关文章推荐：简单权重够不够

10. 让同一份源码适配两种部署根路径

GitHub Pages 使用 /ryuho/，Vercel 使用 /。部署差异只保留在 url 与 root，其余路径由 helper、生成器和同一套审计处理。

关联阅读：同一套 Hexo 源码如何同时部署到 GitHub Pages 和 Vercel

深入工具与运行链路

  • 11. 建立审计模型：静态站点审计器应该检查什么。从源码、产物和对象关系三个层面定义发布契约。
  • 12. 工程化内容生产：个人博客的内容生产流程也值得工程化。用脚手架、工程日志、元数据与双环境验证降低发布摩擦。
  • 13. 改造本地主题：从通用主题到个人表达：我如何改造 Hexo 主题。让首页、文章页和全局布局共同表达内容定位。
  • 14. 设计搜索索引契约：一个可靠的静态站搜索索引应该包含什么。从消费者需求反推字段、清洗、摘要和 URL 语义。
  • 15. 为静态站建立可观测性：为什么个人博客也需要可观测性。观察内容输入、构建日志、审计结果和部署差异。

整理内容结构与可信表达

  • 16. 设计信息架构：如何设计一个不会越写越乱的技术博客信息架构。让首页、专题、项目、分类、标签、归档和搜索各自承担明确责任。
  • 17. 区分系列、标签和分类：文章系列、标签和分类分别解决什么问题。分别表达阅读顺序、具体概念与长期主题。
  • 18. 补齐完整 SEO 链路：静态站点的 SEO，不只是加几个 meta 标签。把内容元数据、URL、站点发现和产物验证连成一条链。
  • 19. 理解 49 项门禁的层次：从 0 到 49 项检查：质量门禁是怎样逐步长出来的。重点不是数字，而是从存在性走向全站一致性的判断过程。
  • 20. 写可信的项目复盘：个人项目如何写出可信的项目复盘。从仓库证据出发，分开事实、解释、结果与边界。

明确产品边界与长期维护

  • 21. 盘点无后端产品能力：没有后端，博客还能做到哪些产品化能力。搜索、推荐、离线、订阅和质量保障都可以在静态边界内成立。
  • 22. 解释本地主题选择：为什么我没有直接使用成熟 Hexo 主题。这不是否定成熟方案，而是选择与当前需求匹配的控制权。
  • 23. 识别五类维护债务：技术博客最容易积累的五类维护债务。持续处理内容、链接、依赖、部署和界面债务。
  • 24. 约束 AI 辅助写作：AI 辅助写作如何避免生成“正确但空洞”的文章。先建证据表，再生成、核验和去模板化。
  • 25. 决定保留与删除：个人博客维护一段时间后，我保留了什么、删掉了什么。根据当前仓库可验证的事实复盘维护范围。

这个专题关注什么

  • 静态站点的多环境路径处理
  • 内容源文件与构建产物审计
  • 搜索、RSS、sitemap 和 PWA 的维护边界
  • 个人项目如何避免功能膨胀
  • 技术写作如何与工程实践互相促进
