项目与实践

Ghost-Author 的工程项目、AI 实践和站点迭代记录。

这里收集我正在沉淀的工程实践。相比单篇文章，项目页更关注“做了什么、为什么这样做、如何验证、还能继续优化什么”。

AI 工程实践

AI 功能评测集

目标：让 AI 功能上线前不再只靠主观体验判断质量。

已沉淀：

  • 评测样本的最小字段设计
  • 核心成功样本、边界样本、反例样本、长尾样本、回归样本的分层
  • 从人工评分过渡到自动化评测的路径

关联阅读：AI 功能上线前，先写评测集

RAG 可用性链路

目标：把 RAG 从“文档向量化 Demo”推进到可解释、可验证的知识问答系统。

已沉淀：

  • 文档治理、切分、召回、排序、回答约束的拆解
  • 向量召回和关键词召回的组合思路
  • 召回率、精确率、忠实度、可操作性的验证指标

关联阅读：RAG 不是把资料塞进向量库

智能体产品边界

目标：设计可控的半自动智能体流程，避免一开始就追求高风险全自动。

已沉淀：

  • 建议型、草稿型、确认型、自动型四级能力模型
  • 工具权限分层和高风险动作确认机制
  • 过程轨迹、失败恢复和审计意识

关联阅读：智能体产品别先追求全自动

AI 应用可观测性

目标：让 AI 应用上线后能持续看见质量、成本、风险和人工接管情况。

已沉淀：

  • 请求层、输入层、上下文层、输出层、成本层的观测拆分
  • 用 trace_id 串联模型、提示词、检索、工具调用和反馈
  • 从稳定性指标走向质量定位和成本治理

关联阅读：AI 应用上线后，要先看见什么

博客工程化

这个站点本身也是一个持续迭代的小项目。

已完成：

  • GitHub Pages 与 Vercel 双路径构建配置
  • 静态产物审计：SEO、sitemap、RSS、manifest、内部链接和图片尺寸
  • 本地搜索索引，不依赖临时 CDN
  • service worker 预缓存核心页面和最新文章
  • 文章页相关推荐，串联同主题内容
  • AI 工程专题页，按生产落地路径组织连续阅读
  • 博客工程化专题，串联定位、体验、部署和质量门禁

继续优化方向：

  • 只在出现真实项目事实和可复用经验时补充复盘
  • 为重点文章补充架构图、流程图和评测样例

最新复盘：从能构建到敢发布：为 Hexo 博客建立质量门禁

搜索复盘：静态博客搜索为什么选择零 CDN 依赖

离线策略复盘：个人静态站的离线策略：为什么选择网络优先

图片管线复盘：图片优化应该发生在源码还是构建产物

内容推荐复盘：零后端的相关文章推荐：简单权重够不够

双部署复盘：同一套 Hexo 源码如何同时部署到 GitHub Pages 和 Vercel

审计模型：静态站点审计器应该检查什么

内容工程：个人博客的内容生产流程也值得工程化

信息架构：如何设计一个不会越写越乱的技术博客信息架构

产品边界：没有后端，博客还能做到哪些产品化能力

维护复盘：个人博客维护一段时间后，我保留了什么、删掉了什么
